# Exporting & Saving

How to load, save, and export mikGen paths.

## Copy & Paste Code

| Shortcut | Action |
|----------|----------|
| Ctrl + C | Copy code for the selected segments |
| Ctrl + Shift + C | Copy code for the whole path |
| Ctrl + X | Cut the selected segments as code |
| Ctrl + V | Paste code back into the path |

Pasting parses the code back into segments. So you can directly copy an entire path in your library the way it is and paste it into mikGen.

## Edit Templates

Every segment kind owns one line of code, written as a template. To change how a format exports,
press `Settings`, `Edit Templates`:

<img src={require('./img/export/edittemplates.png').default} width="100%"  style={{ paddingBottom: '20px' }} />

Each row is the template for the segment named above it. Anything inside `${}` is a placeholder
filled in per segment; everything else is copied out literally. So this template:

```
chassis.pid_odom_set({{${x}_in, ${y}_in}, ${drive_directions}, ${speed}}, ${slew});
```

exports as:

```cpp
chassis.pid_odom_set({{24_in, 36_in}, fwd, 110}, true);
```

`Reset` restores every template for the current format to its built-in
version, and `Save` or pressing `Enter` applies your edits. 

### Placeholders

| Placeholder | Value |
|----------|----------|
| `${x}` `${y}` `${angle}` | The segment's position and heading. On a turn, `${x}` and `${y}` are the point being faced |
| `${distance}` | Distance for a distanceDrive or strafeDrive |
| `${time}` | Wait time in milliseconds |
| `${c1x}` `${c1y}` `${c2x}` `${c2y}` | Bezier control points, for libraries that take a curve directly |
| `${points:N}` | Expands a curve into a waypoint vector, one point every `N` inches |
| `${anyConstant}` | Any constant by name, e.g. `${max_voltage}`, `${kp}`, `${drive_direction}` You can find all constant names by reading exported txt files |
| `${0:anyConstant}` | A constant from one specific group, by position. See [below](#0key-picking-one-constants-group) |
| `${kBuilder}` | The library's block of non-default constants, where the format has one |

Two more behaviors worth knowing:

- **`${kBuilder}` disappears when empty.** If the segment is on default constants there is nothing
  to emit, and writing `, ${kBuilder}` drops the comma along with it rather than leaving
  `drive_to_pose(24, 48, 45, );`.

### `${0:key}`: picking one constants group {#0key-picking-one-constants-group}

A segment usually carries more than one set of constants. An EZ-Template drive carries two: drive
constants and heading constants, each with their own `p`, `i`, `d`. The `Constants` panel shows
them as separate headers, and they are numbered in that order, starting at zero.

A bare `${p}` cannot tell them apart. `${0:p}` takes it from the first group, `${1:p}` from the
second:

```
chassis.set_drive_pid(${distance}_in, ${0:speed}, ${0:slew});
chassis.pid_${0:wait}();
```

:::warning
When a key exists in **more than one** group, a bare `${key}` does not read the first group. It
reads the **last** one. So on a segment whose second group also carries `speed`, writing
`${speed}` exports the second group's speed, and the Max Speed slider, which edits the first
group, appears to do nothing.

:::note
Editing templates changes what pasting can parse. If you rewrite a template and then paste older
code, it will not match. Reset returns the format to its built-in templates.
:::

### `${points:N}`: expanding a curve into a waypoint vector {#points-expanding-a-curve-into-a-waypoint-vector}

Most libraries have no call that takes a bezier. `${points:N}` bridges that: it samples the curve
and writes out the points, one every `N` inches, so a library that can drive through a list of
points can drive a curve.

It needs two rows. The template says where the vector goes, and the `point` row underneath says
what one entry looks like:

```
chassis.${0:pp_mode}({${points:2}}, ${0:slew});
chassis.pid_${0:wait}();

point:  {{${x}_in, ${y}_in, ${angle}_deg}, ${0:drive_directions}, ${0:speed}}
```

Inside the point row, `${x}` and `${y}` are that point's coordinates, and every other placeholder
works as it does anywhere else. The `${angle}` term is special: it survives only on the **last**
point, and the whole term including its comma is removed from the others. That is why one row can
produce both shapes:

```cpp
{{5.67_in, 7.31_in}, fwd, 110},          // an in-between point
{{0_in, 30_in, 45_deg}, fwd, 110}        // the last point, when the segment has a heading
```

## Writing to a File

Press `Ctrl+E` or use the Export button to write the path directly into a `.cpp` file in your
project. The generated code is placed between comment markers named after your path, and only
the code between the markers is touched on later exports:

```cpp
// [My Path]
chassis.set_coordinates(0, 0, 0);
chassis.drive_to_point(24, 24);
// [My Path]
```

Two optional modes change how existing code in the file is updated:

- **Merge mode** (on by default): matches segments to the code already in the file, replacing,
  inserting, or deleting lines as needed. Hidden segments are ignored.
- **Replace mode**: only replaces segments that match the type and count in mikGen. Hidden or
  unselected segments are ignored.

:::note
Writing to files uses the File System Access API, which requires a Chromium-based browser
such as Chrome or Edge.
:::

## Project Files

Paths can be saved and loaded as mikGen project files:

<img src={require('./img/export/filebutton.png').default} width="20%"  style={{ paddingBottom: '20px' }} />

Opening a folder shows a file browser sidebar for switching between paths. Your current path
also auto-saves to browser storage, so you can refresh the page safely.

:::note
The underline under the file button means you have unsaved changes. You can only save if you use a Chromium browser, like Chrome or Edge.
:::

:::important
For ease of use, store your path files inside a folder inside your library of choice. That way you can commit changes to the path so your
teammates can have updated paths. This allows mikGen to be completely local to you, meaning that your paths are not stored on a database.
:::
