# Getting Started

Build your first autonomous path in mikGen.

## Selecting a Format

To get started, first select the format you will be using.
The format determines which segments are available, what they are named, and what constants they use;
since mikGen matches your chosen library's internals. It is recommended to read your library's documentation:

- [mikLib](https://ethanmik.github.io/mikLib/)
- [LemLib](https://lemlib.readthedocs.io/en/stable/)
- [JAR-Template](https://jacksonarearobotics.github.io/JAR-Template/)
- [EZ-Template](https://ez-robotics.github.io/EZ-Template/)

If your robot is holonomic you can select that here:

## Building Your First Path

To add the start of the path, left click on the field

<img src={require('./img/getting-started/start.png').default} width="50%"  style={{ paddingBottom: '20px' }} />

You can then left click again to add a Drive to Point segment

<img src={require('./img/getting-started/mtp.png').default} width="50%"  style={{ paddingBottom: '20px' }} />

The most common segments are added with these clicks:

| Button | Segment | Description |
|----------|----------|----------|
| Left Click | pointDrive | Drives the robot to a desired (x, y) |
| Ctrl + Left Click | poseDrive | Drives the robot to a desired (x, y, theta) |
| Right Click | pointTurn | Points the robot at the drive segment in front of it, or the field centre if there is none |

Every segment and keybind is listed in [Segment Interfacing](./segment-interfacing.mdx).

A few tips while building:

- Drag any waypoint on the field to move it. Hold `Ctrl` while dragging to snap to the grid.
- New segments are inserted after the currently selected segment.

## Editing a Segment

Click a segment on the field or in the path list to select it.

<img src={require('./img/getting-started/selection.png').default} width="50%"  style={{ paddingBottom: '20px' }} />

Press `Backspace` to delete a
segment and `Ctrl+Z` to undo.

## Copying the Code

Once your path is ready, press `Ctrl+Shift+C` to copy the generated code for the whole path,
or `Ctrl+C` to copy only the selected segments. The output uses your chosen library's API,
so it can be pasted directly into your autonomous routine:

```cpp
chassis.set_coordinates(0, 0, 0);
chassis.drive_to_point(24, 24);
```

mikGen can also write code directly into your project files. See [Exporting & Saving](./exporting-and-saving.mdx).

## Troubleshooting

The most common issue in mikGen is your robot not matching up with the simulation in real life. Here are some reasons why:

| Issue | Solution|
|-|-|
| Odometry wheels have bad build quality; not banded down, not perpendicular, have high friction | Make sure odom point is mounted on a crossbrace, the wheel has two attachment points, and if a two inch odom pod is used, it is doubled and offseted from the other to cover the gaps. If you robot is very consistent with how much it differs from the website then this is likely not the issue. |
| Units are off | Move the robot with a tape measure with odometry values printing, and make sure lateral and horizontal distance match the tape measures reading, just 0.1" difference over 1 foot adds up.  |
| Offsets are off | If you turn the robot 180 degrees, your robot's position should not change, if it does then your offsets are wrong, and you need to remeasure   |
| Not using odom wheels | Make sure you limit acceleration driving as it is very easy for the wheels to slip |
| Robot not started at right position | This is the most common mistake. For optimal alignment, use the field tiles or walls as a reference point to where to place drivetrain. Then at the start of the program, set the odometry where the robot is in mikGen |

:::important
Your robot will not match the website perfectly, there is usually a 1-2 tolerance in a full auton run. Correcting odom values with distance sensors helps a lot
:::
